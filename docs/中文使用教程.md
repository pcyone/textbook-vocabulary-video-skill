# 教材词汇自动化视频 Skill：完整中文使用教程

> 适用对象：英语教师、教材内容创作者、视频号运营者，以及希望用 Codex 批量制作词汇教学视频的使用者。本文依据当前仓库实际代码编写。

仓库：[pcyone/textbook-vocabulary-video-skill](https://github.com/pcyone/textbook-vocabulary-video-skill)

## 一、这个 Skill 能帮你完成什么

这套工具把一份经过确认的教材词汇分期规划，转化为可以发布的教学视频文件。它不是把 PPT 页直接录成视频，而是将每期内容重新组织为九个教学场景，再生成插画、配音、字幕和动画。

默认输出为 1080×1920、30 帧/秒的竖屏 MP4，每期约 45–70 秒，包括中文讲解、英文跟读、校园情境插画和三秒小测。同时交付 SRT 字幕、逐期视频号文案及文案汇总。

例如，Unit 2 的一个批次可以是：

| 期数 | 主题 | 本期重点 |
|---|---|---|
| EP21 | presentation | 展示汇报不只是一份幻灯片 |
| EP22 | mood | in a good mood 的完整搭配 |
| EP23 | mind | mind doing 与 not mind doing |
| EP24 | pack | packing 不再双写 k |
| EP25 | celebrate | celebrate a birthday 直接接宾语 |

这里的期号来自已有规划，并不是工具内置的通用词汇顺序。换一本教材时，需要先建立那本教材自己的规划。

### 明确边界

Skill 不会自动登录视频号、替你发布、创建定时任务，也不会在做完五期后继续制作下一批。当前管线按七年级上册的目录结构实现；其他年级、横屏课程、数字人视频等需要适配，不能只更换标题便视为已支持。

它也不是完全脱离人的系统。教材内容核对、新系列样片确认、逐期画面检查和必要的发音抽听仍然保留。

## 二、理解三个不同的目录

使用前先区分三个位置，可以避免大部分操作错误。

| 目录 | 用途 | 是否包含教材和成片 |
|---|---|---|
| Skill 目录 | 保存指令、辅助工具和最小模板 | 默认不包含 |
| 视频项目目录 | 保存源稿、图片、音频、配音配置和渲染结果 | 包含制作数据 |
| 交付目录 | 汇总本批已经通过检查的最终文件 | 包含 MP4、字幕、文案 |

安装 Skill 不等于恢复完整视频项目。只从 GitHub 下载仓库，不会得到此前 Unit 1、Unit 2 的教材、分期规划、插画、背景音乐或已生成视频。

## 三、准备工作

需要准备：

- 可以运行本地任务的 Codex 环境。
- Node.js 22 或以上版本及 npm。
- FFmpeg 和 ffprobe。
- 首次安装依赖、下载渲染浏览器和调用配音服务所需的网络权限。
- 可用的豆包 TTS 配置及相应服务权限、额度。
- 当前环境可用的图像生成工具；仓库本身不提供独立图像生成服务。
- 可以显示中文和音标的字体。
- 有权使用的教材资料、插画参考和背景音乐。

图像生成、TTS、模型调用及其他服务可能产生费用。具体价格和许可按所用服务的实际规则确认，本文不承诺免费、不提供固定费用估算。

这套模板曾在 macOS 环境验证。Windows、Linux 或其他电脑上，特别需要重新检查字体、音标和断行，不能默认画面完全一致。

## 四、安装 Skill

### 方法 A：让 Codex 帮你安装

可以直接提出：

> 请从 https://github.com/pcyone/textbook-vocabulary-video-skill 安装教材词汇自动化视频 Skill。如果已有同名 Skill，请先检查版本，不要直接覆盖我的本地修改。

根据环境提示完成必要的权限确认。安装完成后，重新加载 Skill 或开启能够识别新 Skill 的会话。

### 方法 B：手动安装

以下命令面向 macOS/Linux 的终端。目标目录必须不存在；如果已经安装，请先检查，不要删除后重装。

```sh
git clone https://github.com/pcyone/textbook-vocabulary-video-skill.git "${CODEX_HOME:-$HOME/.codex}/skills/textbook-vocabulary-video"
```

安装后，应能在目标目录下看到 `SKILL.md`、`agents`、`references`、`scripts` 和 `assets`。

如果之前由 Codex 安装的是文件副本，该目录可能没有 Git 信息，不能直接使用 `git pull`。应先区分“克隆仓库”和“复制安装”，再选择更新方式。

## 五、已有项目：最省事的使用方式

如果这台电脑已经有 `knowledge-paper-template` 视频工程，不要再初始化新工程，也不要把 Skill 的模板覆盖进去。

在 Codex 中指定项目和范围：

> 使用 $textbook-vocabulary-video。视频项目是我现有的 knowledge-paper-template，请读取其中对应的 Unit 2 分期规划，继续生成 EP26–EP30，并整理视频号发布文案。沿用已确认的画风、配音和竖屏模板，不改动之前完成的视频。

如果项目不在当前工作目录，把实际完整路径一起提供。Skill 会先定位相关文件，而不是仅凭期号猜测内容。

已有成片的期数，应先检查是否真正完成。若视频合格但缺少文案，只补文案即可，不应为了补文案重新调用配音和重渲染。

## 六、新电脑：初始化视频工程

下面是可执行流程，使用者也可以把要求交给 Codex 代为操作。路径变量需要换成你的实际位置。

```sh
export SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills/textbook-vocabulary-video"
export PROJECT_DIR="$HOME/Documents/vocabulary-video-project"
```

`PROJECT_DIR` 必须是尚不存在的新目录。然后执行：

```sh
node "$SKILL_DIR/scripts/init-project.mjs" "$PROJECT_DIR"
cd "$PROJECT_DIR"
npm ci
```

初始化会复制最小 Remotion 模板并建立数据、素材和输出目录。它不会自动安装依赖、自动配置配音，也不会生成教材内容。`npm ci` 根据锁文件安装依赖，避免随意升级造成不一致。

检查环境：

```sh
node --version
node -p process.execPath
ffmpeg -version
ffprobe -version
npm run typecheck
```

同一台电脑可能装了多个 Node.js。某个目录下执行成功，不代表另一个目录解析到的版本相同；遇到版本错误时，检查实际执行路径。

## 七、配置配音与素材

### 配音配置

在项目根目录通过编辑器建立 `.env.local`，填写你自己的配置。以下只是字段示例，不能直接用于调用：

```dotenv
DOUBAO_TTS_API_KEY=填入你自己的密钥
DOUBAO_TTS_RESOURCE_ID=填入账户可用的资源标识
DOUBAO_TTS_SPEAKER=填入已选择的中文音色
```

可选项包括 `DOUBAO_TTS_MODEL`、`DOUBAO_TTS_ENGLISH_SPEAKER`、`DOUBAO_TTS_ENGLISH_MODEL`。音色和模型标识要与当前账户及服务相匹配，不要凭空填写。

也可以让 `KNOWLEDGE_TTS_ENV_FILE` 指向另外一个本地配置文件。随附的新模板支持直接使用环境变量；已有旧工程可能有自己的读取逻辑，应检查后使用。

不要把密钥粘贴到聊天记录，不要提交 `.env.local`，也不要把它放进用于公开分享的压缩包。

### 图片与背景音乐

每期插画放入项目的 `public/microcourse/assets/`。插画通常为 4:3，最终成片仍是 9:16。不要在生成图里写英文或音标，这些文字由模板排版。

当前配音混音流程需要 `public/microcourse/assets/bgm.wav`。仓库没有附带音乐，应提供有权使用的背景音乐。想完全取消配乐，需要明确调整混音流程，不能简单删除文件后继续运行。

## 八、准备教材、规划和源稿

首先提供出版社、年级、册次、版次及本次单元资料。例如：上海教育出版社七年级上册，2024 新版，Unit 2 School life。不要与旧版的单元顺序混用。

推荐分两步提出任务。

第一步，建立规划：

> 请根据我提供的教材词表和课件，编写本单元的视频分期规划。每期明确主词、词义、词形、搭配、例句、易错点和三秒小测，并保留教材来源。先给规划，不生成整批视频。

第二步，确认后制作：

> 规划已确认。请使用 $textbook-vocabulary-video 先制作一条样片。内容按教材要求处理，拓展内容要标明，不把理解词当作必背词测试。

新系列的第一条可以先完成内容审核、配音和样片渲染，作为“待确认样片”交付。当前批次预检和正式交付工具要求已有样式批准引用，因此不要为了通过它们而伪造批准；用户确认样片后，再记录批准信息、重建相应时间线并进入正式批量流程。

源稿由 Codex 按示例结构编写，不需要普通使用者手写 JSON。完整字段参考仓库的 `assets/lesson.example.json`。这个文件故意保留待审核状态，不能把标记改成“已审核”就当作完成了教学核对。

## 九、制作一批视频

### 推荐：自然语言调用

> 使用 $textbook-vocabulary-video，按已确认的规划制作 EP21–EP25。保持九场景、1080×1920 竖屏和中英文分段配音，问题读完后留足三秒再揭示答案。逐期检查后交付 MP4、SRT 和视频号发布文案，不要自动发布。

这是一条制作请求，不是指令一发出就能立刻完成。Codex 还需要读取资料、准备素材、调用服务并通过验收。

### 需要手动操作时

下列命令以两期为例，前提是两期源稿已审核、已有样片批准、插画与音乐就绪。`u2-21-presentation` 是文件标识，不是任意可以替换的显示标题。

先做预检：

```sh
node "$SKILL_DIR/scripts/workflow.mjs" check \
  --project "$PROJECT_DIR" --unit unit02 \
  u2-21-presentation u2-22-mood
```

预检通过只说明检查到的本地条件满足要求，不代表 TTS 密钥已鉴权成功、额度充足，或所有字体已经验收。注意查看返回的 `ttsConfigPresent` 和相关说明。

进入项目目录，依次执行：

```sh
cd "$PROJECT_DIR"
node scripts/run-microcourse-batch.mjs voice --unit=unit02 u2-21-presentation u2-22-mood
node scripts/run-microcourse-batch.mjs render --unit=unit02 u2-21-presentation u2-22-mood
node scripts/check-microcourse-audio.mjs u2-21-presentation u2-22-mood
```

每一步完成后检查结果再运行下一步。批处理脚本可能在一集失败后继续处理其他集，因此要查看最终失败名单，不能只看到其中一条 DONE 就认为整批完成。

同一个项目不能同时运行两个渲染进程，因为它们共享构建目录。需要先检查画面时，可以将 `render` 改为 `stills`，但静帧检查不是最终视频。

## 十、如何判断视频真正完成

每期输出目录为：

```text
out/grade7/semester1/unit02/u2-21-presentation/
```

重点检查三个方面：

1. 内容：词义、拼写、音标、搭配、例句、小测答案及下一期预告是否正确。
2. 视听：九宫格预览没有遮挡、断词、缺字；实际播放时发音、节奏和字幕正常；三秒小测没有提前泄露答案。
3. 技术：视频、音频检查报告通过，成片与当前源稿匹配，文件可以正常播放。

音频检查可以发现静音和响度问题，但不能证明发音一定正确。尤其是 present 这样的同形异音词，需要结合语境并抽听。

先检查技术结果：

```sh
node "$SKILL_DIR/scripts/workflow.mjs" verify \
  --project "$PROJECT_DIR" --unit unit02 \
  u2-21-presentation u2-22-mood
```

逐期完成视觉检查后，再交付到一个不存在的新目录：

```sh
node "$SKILL_DIR/scripts/workflow.mjs" deliver \
  --project "$PROJECT_DIR" --unit unit02 \
  --output "$PROJECT_DIR/delivery/EP21-EP22" \
  --visual-reviewed u2-21-presentation u2-22-mood
```

`--visual-reviewed` 是对“已经看过画面”的声明，不是让程序自动替你看画面的功能。不能为了绕过门禁直接填上。

这个交付命令要求逐期 `视频号发布文案.md` 已存在；它负责复制与汇总，不负责自动编写文案。

## 十一、使用交付结果

交付目录会包含每期 MP4、同名 SRT、逐期发布文案，以及 `视频号发布文案汇总.md` 和 `交付检查.json`。

MP4 画面已包含字幕；SRT 是额外字幕文件，可用于后续编辑或其他平台。发布文案可以直接作为标题、正文、标签和置顶评论的基础，发布前再按你的账号定位检查。

制作完成不等于已经发出。你需要在视频号中自行选择成片、填写文案、预览并确认发布。交付报告默认保留 `published: false`。

## 十二、续做、修改与迁移

### 续做下一批

> 使用 $textbook-vocabulary-video，继续完成规划中的 EP26–EP30。复用已批准模板，先检查是否已有完成文件，避免重复生成。

### 只改一条

> 请修改 EP23 的易错点讲解，其他期保持不变。修改后重新生成这一期的时间线、视频、字幕和对应文案，并重新验收。

即使只改屏幕文字，也需要更新源稿对应的时间线并重渲染。语音内容不变时可以复用已有音频缓存，不等于必须重新付费生成所有句子。

### 传到另一台电脑

只需发布：传输最终交付目录即可，另一台电脑不必安装 Node 或 Remotion。

需要继续制作：除了安装 Skill，还要迁移相关规划、源稿、图片、音乐及需要保留的音频缓存；在新电脑单独配置密钥和字体。不要把“公开 Skill 仓库”当作完整项目备份。

### 需要压缩包

> 请把已完成的 EP21–EP25 视频、字幕和发布文案打成一个 ZIP，检查文件数量和解压后的完整性，不包含密钥、缓存或无关教材。

压缩打包需要明确提出，Skill 不会默认生成。

## 十三、常见问题

| 问题 | 应对方法 |
|---|---|
| 找不到 Skill | 检查安装目录、SKILL.md 和当前会话是否已加载 |
| 提示 Node.js 22+ required | 检查版本及实际执行路径，使用已安装的合适版本 |
| 缺少 bgm.wav | 提供有授权的音乐，或明确要求适配无配乐模式 |
| 配音鉴权、额度错误 | 检查账户配置；停止重试，不在聊天中展示密钥 |
| 提示源稿哈希过期 | 源稿已经变化，重新生成该期时间线和视频 |
| 某期超过 70 秒 | 精简讲解，避免强行提速压缩 |
| 排版检查失败 | 缩短长标题、选项或说明，检查字体后重渲染该期 |
| 无法写入交付目录 | 检查权限；工具拒绝覆盖已有目录，可选择新目录 |
| 发布文案缺失 | 补写对应 MD，再验证；不必因此重做合格视频 |
| 没有网络 | 可整理资料和检查已有成片，但不能声称新配音已完成 |

## 十四、第一次使用的最短路径

安装 Skill，打开现有项目，提供教材和明确期数，让 Codex 核对规划；新系列先确认一条样片，然后再批量制作。每批完成后检查视频和文案，再自行发布。

自动化减少的是重复操作，不应省去教材核对、样片确认和最终检查。
